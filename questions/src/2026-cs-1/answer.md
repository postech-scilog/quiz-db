`printf()` 함수는 임의의 개수의 인자를 받을 수 있다는 점에서 특별합니다.
다음 코드들은 모두 아무 문제 없이 컴파일됩니다.

```c
printf("%d", 1);
printf("%d %d", 1, 2);
printf("%d", 1, 2);
printf("", 1);
```

그럼 `printf()` 함수는 어떻게 정해지지 않은 개수의 함수를 받을까요? 우선 `printf()` 함수의 시그니쳐를 봅시다.

```c
int printf( const char* format, ... );
```

시그니쳐의 두 번째 인자가 `...` (ellipsis) 로 되어 있는것을 볼 수 있습니다. 이렇게 처리된 함수의 경우, 컴파일러는 함수가 몇 개의 인자로 호출되던간에 오류라고 처리하지 않습니다. 즉 *내부 구현이 알아서 해라*라는 표시에 가깝습니다.

그럼 구현은 어떻게 해야할까요? `printf()` 함수의 내부 구현은 다음과 같습니다.

```c
int printf(const char* format, ...) {
    int result;
    va_list args;
    va_start(args, format);
    vprintf(format, args);
    va_end(args);
    return result;
}
```

함수가 `va_list` 타입을 생성하고 `va_start()` 함수로 가변 인자 리스트의 시작을 표시, `vprintf()` 함수에 가변 인자 리스트를 넘겨주는 걸 볼 수 있습니다. `vprintf()` 함수는 `va_arg(args, <타입>)` 코드를 호출해 인자들을 가져올 수 있습니다. 마지막으로 `va_end()` 함수를 이용해 가변 인자 리스트의 끝을 표시하면 가변 인자 처리가 완료됩니다.

즉 C에서 가변 인자를 사용 시 컴파일러는 거의 개입하지 않습니다.

그렇다면 필요한 인자의 개수와 실제로 주어진 인자의 개수가 다르다면 어떻게 될까요? 정답은 "정의되지 않은 동작이 발생한다" 입니다. 문제에서 주어진 상황에서 `vprintf()` 함수는 `va_arg()` 를 총 3번 호출할 것이고, 해당 코드는 속도 문제 등으로 인해 경계 검사를 전혀 하지 않습니다. 따라서 2번째 정수를 읽으려고 시도할때부터 쓰레기 값을 읽기 시작할 것입니다.

추가적으로 사실 1번, 3번, 5번 선지도 틀렸다고 할 순 없습니다. 왜냐하면 문제에서 어떤 컴파일러, 어떤 운영체제를 사용하는지 명시하지 않았기 때문에 

- `printf` 함수에 대해 추가적으로 인자 개수 검사를 수행하는 컴파일러를 사용한다면,
- 인자의 개수를 검사하는 `printf` 구현이 사용된다면,
- `printf` 호출을 특별하게 다루는 이상한 운영체제를 사용한다면,

해당 선지들도 정답이 될 수 있습니다. 

그리고 굉장히 특별한 상황에서는 2번 선지도 정답이 될 수 있습니다. 함수 호출 시 보통 함수 인자는 레지스터에 저장되고 `call` 명령을 통해 함수가 호출되지만, 실제로는 컴파일러의 결정에 따라 이런 과정이 일어나지 않을수도 있습니다. 만약 컴파일러가 `printf()` 함수의 호출을 인라인 (호출되는 함수의 코드를 그대로 박아넣기) 하기로 결정한다면 인자는 스택을 통해 넘겨질 수 있습니다. 또한, 특정 컴파일러는 스택의 값을 모두 0으로 채우는 결정을 하기도 합니다. (gcc + `-finit-local-zero` 플래그)
이런 굉장히 특별한 상황에서는 항상 `0 0 0` 이 출력될 수 있습니다.

이러한 문제들은 결국 논리적 대상인 프로그래밍 언어와 그 구현인 컴파일러는 별개의 대상이기 때문입니다. 이 둘을 혼동하지 않고 잘 구분해 공부하도록 합시다.
