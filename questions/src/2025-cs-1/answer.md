현대 운영체제에서는 실제 램의 공간 (물리 메모리) 보다 더 많은 메모리를 활용할 수 있도록 **가상 메모리** (virtual memory) 를 활용합니다.

* 프로그램은 가상 메모리 주소를 이용해 메모리에 접근합니다.
* 운영체제는 가상 메모리 주소를 **페이지**라는 단위 (보통 4KiB) 로 나눠 관리합니다.
* 램 공간이 부족하다면 사용하지 않는 페이지의 내용을 디스크에 저장하고 나중에 필요할 때 다시 읽어들이는 방식으로 공간을 확보합니다. 이 작업을 **스왑**이라고 부르며, 보통 디스크의 **스왑 파티션**에 이 내용이 저장됩니다. 어떤 페이지가 스왑될지는 운영체제별 다른 알고리즘에 의해서 결정됩니다.

**페이지 테이블**은 각 페이지의 상태를 기록하고 있는 자료 구조입니다. 운영체제마다 어떤 상태를 기록하는지는 다를 수 있지만, 대부분 다음과 같은 상태를 포함합니다.

* Reference bit: 페이지가 최근에 참조되었는지를 나타내는 비트.
* Dirty bit: 페이지의 내용이 변경되었는지를 나타내는 비트.

Reference bit는 페이지 교체 알고리즘을 구현하는데에 보통 사용됩니다. 예시 중 하나인 LRU (Least-Recently Used) 알고리즘은 reference bit를 이용해서 최근에 사용된 적이 없는 페이지를 스왑하는 것을 지향합니다. 운영 체제는 페이지에 접근이 일어날 때 reference bit를 설정하고, 이를 주기적으로 리셋함으로써 최근 참조된 페이지와 그렇지 않은 페이지를 구분할 수 있는 것입니다.

Dirty bit는 스왑 과정을 최적화하기 위해서 사용됩니다. 디스크에서 스왑해온 페이지의 내용이 메모리 상에서 변경된 후 이를 다시 디스크에 작성해야 하는 상황을 생각해 봅시다. 운영 체제는 dirty bit를 이용해 이 비트가 설정되어 있지 않은 경우 페이지 내용을 디스크에 작성하는 과정을 생략할 수 있으며, 덕분에 시간 (디스크는 램과 비교해 굉장히 느립니다) 과 수명에 영향을 주는 것을 방지할 수 있습니다.

(TMI: 우리가 주로 사용하는 TLC SSD는 스왑이 자주 일어날 경우 유의미하게 수명이 감소할 수 있습니다. 램이 부족한 경우 램을 늘립시다.)

문제의 1, 2, 3번 선지는 reference bit에 대해, 4번 선지는 dirty bit에 대해서 설명하고 있습니다. 따라서 정답은 1, 2, 3입니다.
